# 任务书

**任务编号**：T-006（阶段一收官 · demo 装配与全链路验证）
**切片名称**：examples/demo 最小可运行后台 — 装配 T-001~T-005 五大块，跑通登录+RBAC+数据权限+配置+日志
**目标后端**：Gin（纯 Go；不碰 PHP、不碰前端）
**契约版本**：openapi 不升版（demo 是装配样例，不新增对外契约）
**前置依赖**：T-001~T-005 全部已收尾。

> **性质**：这是**装配样例 + 回归环境**，不是底座库代码。位于 `server/examples/demo/`。
> 作用（架构 §10）：① 证明底座五大块能协同跑通；② 新应用 starter（BenxinKP backend-gin 照此起步）；③ 底座改动的回归环境。
> **关键区别**：demo 是消费方视角，**允许出现具体装配值**（注入真实 Redis 实现、本地存储驱动、超管角色 code、各 Store/Provider/Center 的具体组装）——这不违反"底座业务中立"，因为这些具体值在 demo 里、不在 server 库里。但**真密钥/真凭证不进仓库**（用占位 + .gitignore，沿用既有纪律）。

---

## 1. 目标（一句话）
在 `server/examples/demo/` 装配 T-001~T-005 全部能力，提供一个能 `go run` 起来的最小后台：迁移执行器一键建表 → 登录拿令牌 → 带令牌走 RBAC 鉴权 + 数据权限过滤 → 读写配置触发热加载 → 操作/登录日志落库；并把历次积压的 daxing 真人验收项汇总成一张可照做的清单。

---

## 2. 范围

### ✅ 包含
1. **装配主程序** `server/examples/demo/main.go`（+ 必要的 wiring 文件）：
   - 读 demo 配置（YAML，viper）；连 MySQL + Redis（localhost）。
   - **用 T-005 迁移执行器一键建表**（替换 {{TABLE_PREFIX}} 为 demo 前缀，执行 spec/migrations 全部 SQL）。
   - 装配各模块**具体实现**：crypto（CBC 中间件 + GCM crypter）、auth（TokenService + Argon2id hasher + 图形验证码 + Redis 各 Store + GormUserProvider + LoginLogger）、rbac（Enforcer + PolicySync + Authz/RequirePerm + 超管角色 code + hashid hasher）、system（字典/参数/日志/文件 + 操作日志中间件）、config（ConfigCenter + RedisConfigCache + RedisPublisher/Subscriber）、response（Registry 注册全部码 + 唯一渲染）。
   - **装配自检**：关键依赖（如 hashid hasher、各 Store）非 nil 校验，缺失则启动 fail-fast（呼应 T-003b "enc 非 nil" 装配纪律）。
   - 注册全部 sys/* 路由（复用各模块 RegisterRoutes），挂 JWT + Authz + 操作日志中间件。
2. **种子数据**（demo 初始化，幂等）：
   - 超级管理员角色（code 与配置注入的 SuperAdminRoles 一致）+ 一个超管用户（Argon2id 预哈希，密码来自 demo 配置/环境变量，不硬编码明文）。
   - 一组基础菜单/权限点（sys:* 通用权限码，覆盖 demo 要演示的接口）。
   - 几个部门 + 普通用户（不同 data_scope 的角色），供数据权限演示。
   - 种子用 upsert/存在即跳过，可重复运行。
3. **启动与验证文档** `server/examples/demo/README.md`：
   - 如何起依赖（docker-compose.dev.yml）、如何配置（demo config 示例）、如何 `go run`。
   - 一份**端到端验证脚本/curl 清单**：captcha→login→带 token 调受保护接口→数据权限范围演示→改配置触发热加载→查操作/登录日志。
4. **daxing 真人验收清单汇总**（demo README 或独立 md）：把 T-001~T-005 历次"用到时补"的真人验收项汇总成一张照做即清账的清单（见 §7）。
5. **demo 冒烟测试**（可选但推荐）：一个 `//go:build integration` 的 demo 级 e2e 测试，起真依赖后跑通核心链路（登录→鉴权→数据权限），作为底座回归环境的自动化兜底。

### ⛔ 不包含
- 任何业务概念（内容/会员/支付）——demo 只演示底座通用能力。
- admin 前端联调 → 下一片。
- 新增底座库功能/接口/错误码 → demo 只装配，不改 server 库（若装配中发现库的缺陷，单独提，不在 demo 里打补丁绕过）。
- 生产部署配置 → 后续。

## 4. 装配契约（关键：正确组装，不是新写）

### 4.1 启动顺序
1. 加载 demo 配置（含 table_prefix、redis_prefix、各密钥占位、超管角色 code、Argon2/captcha/lockout/file 参数、GCM 主密钥）。
2. 连 MySQL/Redis；fail-fast 校验（沿用各模块的启动校验：aes/gcm key=32B、密钥非空、阈值合法等）。
3. **迁移执行器 Up()**：建表（幂等）。
4. 装配各模块（DI 注入具体实现）；**装配自检**关键依赖非 nil。
5. 种子数据（幂等 upsert）。
6. response.Registry 注册全部码（含各段）；启动 HTTP server。

### 4.2 路由总装
- 公共：`/auth/captcha` `/auth/login`（无鉴权）。
- 受保护：所有 `/sys/*`（JWT + Authz/RequirePerm + 操作日志中间件）；`/auth/refresh` `/auth/logout`。
- C 端演示（可选）：一个走 crypto CBC 信封中间件的示例只读接口，证明 T-001 信封在装配中可用。

### 4.3 装配自检（呼应历史教训）
- hashid hasher 非 nil（否则 T-003b 的 ResponseEncoder 降级裸 ID——demo 必须注入）。
- 各 Redis Store（replay/blacklist/captcha/lockout/configcache）非 nil 且连通。
- 超管角色 code 与种子角色一致（否则超管短路失效）。
- ConfigCenter 的 RedisPublisher/Subscriber 起协程成功。

---

## 5. 安全要求
1. **真密钥不进仓库**：demo config 用占位 + `.example`；真 aes/gcm/jwt 密钥、超管密码经环境变量或本地 *.local.yaml（已 gitignore）注入；仓库内无任何真实密钥/密码明文。
2. **超管密码**：种子超管的密码不硬编码明文，来自配置/环境变量，且以 Argon2id 哈希存库。
3. **装配不削弱安全**：demo 必须挂齐 JWT + Authz + 操作日志中间件 + crypto（如演示 C 端）；不得为"方便演示"裸奔或关鉴权。
4. **沿用各模块安全**：脱敏、数据权限收紧、加密参数脱敏、文件穿越防护等在 demo 中均生效（装配不绕过）。
5. demo 是样例但仍守纪律：前缀随实例、DI、头注释五项。

# 任务书

**任务编号**：T-007a（admin 前端 第 1/2 子切片：地基）
**切片名称**：admin 前端地基 — 请求层封装（JWT + 统一错误码 + hashid）+ 登录页（含图形验证码）+ 路由/布局框架 + Pinia + 主题/i18n 骨架
**目标**：`admin/`（Vite + Vue 3 + TS + Element Plus；纯前端，不碰 Go/PHP）
**契约依据**：后端已 e2e 验证收官（HEAD b1d823c）。对接 openapi v0.8.0 的统一包络与 auth 接口。
**前置依赖**：T-001~T-006、T-003d（后端可信、demo 可跑）。前端连本地 demo 后端联调。

> **admin 前端拆分**：**T-007a（本片）** = 地基（请求层/登录/框架/骨架）；T-007b = 动态路由 + v-permission + x-table 配置化 CRUD + sys 模块样例页。a → b。
> **决策已定**：admin **不接 CBC 加密信封**（那是将来 C 端 uni 的事；sys 接口走 JWT 明文 over HTTPS）；自建脚手架，**不引第三方 admin 模板**（依赖可控 + 仅开源素材许可）。

## 1. 目标（一句话）
把 `admin/` 从脚手架做到"能登录进系统、有基础布局与受保护路由框架、请求层正确对接后端统一包络/错误码/JWT/hashid"的可运行地基，为 T-007b 的动态路由与 CRUD 铺好底。

## 2. 范围

### ✅ 包含
1. **脚手架确认与依赖**（基于已有 `admin/` Vite+Vue3+TS）：Element Plus、Pinia、Vue Router 4、Axios、UnoCSS（架构既定）；**仅开源素材**（Element Plus MIT、图标 MIT/Apache、字体 OFL/Apache/MIT/ISC/CC0），不引第三方 admin 模板/商业字体/Font Awesome Pro。
2. **请求层封装** `src/request/`（核心）：
   - Axios 实例 + 拦截器；baseURL 配置化（.env）。
   - 请求拦截：注入 JWT `Authorization: Bearer <access>`。
   - 响应拦截：解统一包络 `{code,message,data}`——`code==0` 取 data；非 0 按错误码处理（提示 message、特定码特殊处理如 401→刷新或跳登录、403→无权提示）。
   - **令牌刷新**：access 过期（401/特定码）时用 refresh 自动刷新重试一次；refresh 也失效则跳登录。
   - hashid：对外 ID 都是字符串 hashid，前端**透明透传**（不解码、原样用于详情/删除路径参数）。
   - 错误码表：与后端 errcode 段对齐（前端维护一份 code→提示文案映射或直接用后端 message）。
3. **登录页** `src/views/login/`：
   - 调 `/auth/captcha` 拿图形验证码（base64 PNG 显示）；`/auth/login` 提交 username/password/captcha；成功存令牌、跳首页。
   - 处理后端错误码：错误凭证、需验证码、验证码错、账号锁定、账号禁用——按 message/code 友好提示。
   - 登出调 `/auth/logout`。
4. **路由与布局框架** `src/router/` `src/layout/`：
   - 公共路由（登录页）+ 受保护路由框架（带 layout 的容器）；路由守卫：未登录跳登录。
   - 基础布局：响应式（PC/平板/手机）侧边栏 + 顶栏 + 内容区；侧边栏菜单**本片先用静态占位**（动态路由 T-007b 接 `/sys/auth/menus`）。
   - **本片不做动态路由/按钮权限**（留 T-007b），但路由框架要为其预留接入点。
5. **状态管理** `src/store/`（Pinia）：user store（令牌、当前用户信息、登出清理）；app store（侧边栏折叠、设备类型等 UI 态）。令牌持久化（localStorage/cookie，注意 XSS/CSRF 权衡，执行端说明所选与理由）。
6. **主题 + i18n 骨架** `src/theme/` `src/i18n/`：暗色 + 主题色切换骨架；i18n 框架搭好（中文默认 + 预留 en），文案走 key（不硬编码散落）。
7. **环境与运行**：`.env` 配置（API baseURL 等，占位、真值 .env.local gitignore）；`npm run dev` 能起、连本地 demo 后端跑通登录。

### ⛔ 不包含
- 动态路由（消费 menus）、`v-permission` 按钮指令（消费 perms）、x-table 配置化 CRUD、sys 模块业务页 → **T-007b**。
- CBC 加密信封请求层 → 不做（admin 不需要；预留注释位）。
- 任何业务页面（内容/会员/支付）。
- 后端改动（前端纯对接；若发现后端契约问题，单独提，不在前端打补丁绕过）。

## 4. 契约对接（关键：与已验证后端严丝合缝）

### 4.1 统一响应包络
- 所有响应 `{ code:int, message:string, data:any }`；`code==0` 成功取 data；非 0 为业务错误（按 code/message 处理）。
- 分页 data：`{ list, total, page, page_size }`（与后端一致；字段名以后端实际为准，执行端核对 openapi）。

### 4.2 认证接口（对接 T-002）
- `POST /auth/captcha` → `{ captcha_id, image_base64, expires_in }`。
- `POST /auth/login` `{username,password,captcha_id?,captcha_code?}` → `{ access_token, refresh_token, ... }`。
- `POST /auth/refresh` `{refresh_token}` → 新令牌对。
- `POST /auth/logout`（Authorization 带 access）。
- JWT 放 `Authorization: Bearer`；access 过期自动 refresh 一次。

### 4.3 错误码处理（对接 errcode 段 + response.Registry）
- 401（token 失效/过期）→ 尝试 refresh，失败跳登录。
- 403（ERR_FORBIDDEN，无权）→ 友好提示，不跳登录。
- 423（账号锁定）/ 验证码相关码（需验证码/验证码错）→ 登录页对应提示。
- 其余非 0 → toast message。
- 执行端核对 openapi v0.8.0 的码与 HTTP 映射，前端处理与之一致。

### 4.4 hashid
- 所有 ID 字段是字符串 hashid；前端**原样透传**（列表拿到的 id 直接用于详情/删除 URL），不尝试解码。

## 5. 要求与约束
1. **仅开源素材**（宪法级）：字体/图标许可 OFL/Apache/MIT/ISC/CC0；不引商业字体、Font Awesome Pro、第三方 admin 模板。CREDITS 记录引入的素材与许可。
2. **令牌存储安全**：说明 access/refresh 存哪（localStorage vs cookie）及 XSS/CSRF 权衡；不在 URL 带令牌；登出彻底清理。
3. **不泄漏敏感**：前端不打印令牌/密码到 console（生产构建）；错误提示不暴露后端内部细节。
4. **配置化**：API baseURL 等走 .env，真值 .env.local（gitignore）；不硬编码后端地址/密钥。
5. **代码头注释五项到秒**：TS/Vue 用块注释；@project 用 `本心通用管理后台 / BenxinAdminPro`（admin 属底座前端）。
6. **响应式**：布局适配 PC/平板/手机（架构要求）。
7. **i18n**：文案走 key，不散落硬编码中文（骨架阶段至少框架到位、登录页文案走 key 示范）。
8. **业务中立**：admin 是底座前端，只做通用框架 + 登录 + sys 对接；不掺业务页。

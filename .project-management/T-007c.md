# 任务书：T-007c x-table 增强（只读模式 + 工具栏/行操作插槽 + 列筛选/排序）

**任务编号**：T-007c
**切片名称**：x-table 增强（承重组件加厚，为后续 sys 页提供能力）
**目标后端**：admin 前端（Vue3 + TS + Element Plus；不碰后端）
**契约版本**：openapi v0.8.1（消费既有接口，本片不改契约）
**前置依赖**：T-007b（x-table 最小版：列+分页+搜索+增改弹窗+删除确认）

---

### 1. 目标（一句话）
把 `<x-table>` 从"最小 CRUD"加厚为**可承载只读列表、自定义工具栏/行操作、列筛选与排序**的复用承重件，且**对 T-007b 既有用户/角色页零回归**。

### 2. 范围
- ✅ 包含：
  - **只读模式**：配置开关关闭内置新增/编辑/删除，仅保留列表+分页+搜索+**自定义行操作**（供日志页：详情/清理）。
  - **工具栏插槽（toolbar slot）**：表格上方可插自定义按钮区（供文件页：上传按钮；其他页：批量操作位）。默认插槽不传则保持现状。
  - **行操作插槽/配置**：自定义行内操作按钮，每个按钮可挂 `v-permission`（无权移除 DOM，沿用 T-007b 指令）。
  - **列筛选**：按列配置可搜索项，筛选条件并入查询参数透传后端（后端是过滤权威，前端只拼参数）。
  - **列排序**：`el-table` `sortable`，排序字段/方向作为查询参数传后端（服务端排序；前端不做内存排序伪装全量）。
  - **向后兼容**：所有新能力走配置可选项，缺省行为 = T-007b 现状；既有用户/角色页**不改或仅最小适配**。
- ⛔ 不包含：
  - **树形**（留 T-007g 菜单页随首个消费方落地）。
  - **导出**（本批 defer）。
  - 列拖拽排序、列显隐持久化、列宽记忆等"锦上添花"（用到再评估，防镀金）。

### 3. 数据模型
- 前端组件，无 DDL。
- **配置 schema 设计**（执行端定稿，需在完成报告附最终 props/columns 配置形态）：
  - 表级：`readonly`、`toolbar`(slot)、查询参数装配（搜索 + 筛选 + 排序合并为一个 query 对象传请求层）。
  - 列级：`filterable`/`sortable`/`prop`/`label`/自定义渲染。
  - 行操作：`actions` 配置（label / perm code / handler / 危险态二次确认）。
- 保持与 T-007b 配置的**平滑演进**，不推倒重来。

### 4. 接口契约
- 不改后端契约；消费既有统一包络 `{code,message,data}` 与分页结构。
- 筛选/排序参数命名需与后端既有 query 约定一致（执行端先读后端 handler 确认参数名，**不臆造**；若后端无对应排序/筛选参数，则该能力对该接口降级为不可用并在偏差标注，不前端伪造）。
- hashid 字符串 ID 原样透传，不解码（沿用 T-007a 请求层约定）。

### 5. 安全要求
- 行操作按钮一律可挂 `v-permission`；**前端权限仅 UX，后端 enforce（T-003d）才是边界**——无权用户即便手拼也被后端 403，不做伪安全。
- 筛选/排序参数前端拼装，后端校验与过滤为权威，前端不假设可信。
- 不在前端打印/缓存敏感字段；沿用 T-007a 的 XSS 缓解（Vue 转义、不打印令牌）。

### 6. 规范约束
- 代码头注释五项到秒（Vue/TS 用块注释）；改既有文件追加 `@updated`。
- 仅开源素材（如新增图标/字体须 MIT/Apache/ISC/OFL 并记 `CREDITS.md`；优先复用既有 Element Plus Icons）。
- 自建脚手架，不引第三方 admin 组件库/表格库。
- 组件 API 命名清晰、可复用、业务中立（不出现任何业务字段名）。

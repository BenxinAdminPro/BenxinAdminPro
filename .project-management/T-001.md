## 4. 接口契约

> 协议层常量（头名前缀、字段名）允许固定为协议默认，但**头前缀做成可配置**（默认 `X-Ca-`），密钥/TTL/窗口/前缀/错误码段全部配置注入。

### 4.1 C 端加密信封（语言中立，PHP 须 parity）

**安全头**（默认前缀 `X-Ca-`，可配）：
- `X-Ca-Timestamp`：Unix 秒（字符串）。
- `X-Ca-Nonce`：客户端随机串，建议 16–32 位 `[A-Za-z0-9]`。
- `X-Ca-Signature`：`base64_std(HMAC_SHA256(hmac_key_bytes, UTF8(SIGNING_STRING)))`。

**请求/响应体**（JSON 包裹）：`{"data":"<BODY_B64>"}`
- `BODY_B64 = base64_std( IV(16B) || AES256CBC_PKCS7(plaintext_bytes) )`。
- 请求：中间件解出 `plaintext_bytes`（应为原始业务 JSON），写回 `c.Request.Body` 供 handler 读取。
- 响应：中间件对 handler 输出的 JSON 加密为 `BODY_B64`，回包 `{"data":...}` 并补 `X-Ca-Timestamp/Nonce/Signature` 响应头。

**规范签名串 SIGNING_STRING**（逐字节固定，`\n` = 0x0A）：
```
UPPER(method) "\n" path "\n" timestamp "\n" nonce "\n" BODY_B64
```
- `path`：不含 query、不含 host 的请求路径（如 `/api/c/foo`）；保持与原始请求一致，不做大小写/编码归一化。
- `BODY_B64`：即 `data` 字段的值（内层 b64 字符串，**非**外层 JSON）。
- 签名只对内层 `BODY_B64` 与头三元组生效，不含外层 JSON，便于跨语言稳定复现。

**密钥来源**：config 以 **base64** 提供 `aes_key`（解码后须**恰好 32 字节**，否则启动 fail-fast）、`hmac_key`（建议 32 字节）。

**校验顺序（请求入站）**：
1. 缺任一安全头 → `ERR_MISSING_SECURITY_HEADERS`。
2. `|now - timestamp| > window(300s)` → `ERR_TIMESTAMP_EXPIRED`。
3. 重算签名比对（恒定时间比较）失败 → `ERR_SIGN_INVALID`。
4. Redis `SETNX nonceKey` 失败（已存在）→ `ERR_NONCE_REPLAY`；成功则 `EXPIRE 600s`（用 `SET NX EX 600` 一次完成）。
5. 解密失败/去填充失败 → `ERR_DECRYPT_FAILED`。
> 顺序要点：**先验时间与签名再落 nonce**，避免攻击者用伪造请求污染 nonce 空间；签名比对用 `hmac.Equal` 等恒定时间方式。

### 4.2 JWT 令牌服务（`server/auth`）

```go
type Claims struct {
    Issuer    string // iss，配置注入
    Subject   string // sub，调用方传入的不透明主体标识（底座不解释其含义）
    TokenType string // tt: "access" | "refresh"
    JTI       string // jti: UUIDv7
    IssuedAt  int64
    NotBefore int64
    ExpiresAt int64
    Extra     map[string]any // 可选自定义 claim（业务自带，底座不感知语义）
}

type TokenPair struct {
    AccessToken  string
    RefreshToken string
    AccessExp    int64
    RefreshExp   int64
}

type TokenService interface {
    // 签发一对令牌；subject 与 extra 由调用方提供，底座不校验业务含义
    IssuePair(ctx context.Context, subject string, extra map[string]any) (TokenPair, error)
    // 解析（不校验黑名单）
    Parse(token string) (*Claims, error)
    // 校验：签名 + 过期 + tt + 黑名单
    Verify(ctx context.Context, token string, expectType string) (*Claims, error)
    // 刷新：校验 refresh → 签发新 access（默认轮换 refresh 并拉黑旧 refresh jti）
    Refresh(ctx context.Context, refreshToken string) (TokenPair, error)
    // 注销：把 jti 写入黑名单，TTL = max(0, exp-now)
    Revoke(ctx context.Context, jti string, exp int64) error
}
```
- 算法 HS256；access/refresh 可用**不同**密钥（`jwt.access_secret` / `jwt.refresh_secret`），均配置注入。
- 默认 TTL：access 2h、refresh 7d（均可配）。`refresh_rotate` 默认 `true`。
- 黑名单仅存 refresh 轮换/显式注销产生的 jti（access 通常靠短 TTL，注销 access 也支持 `Revoke`）。
- **业务中立**：服务不引用用户/角色表，不做密码校验；登录流程在 T-002 调用本服务。

### 4.3 Casbin 接入（`server/rbac`）

`server/spec/rbac/model.conf`（标准 RBAC，act 支持通配，便于后续按需扩展为带域模型）：
```ini
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[role_definition]
g = _, _

[policy_effect]
e = some(where (p.eft == allow))

[matchers]
m = g(r.sub, p.sub) && keyMatch2(r.obj, p.obj) && (r.act == p.act || p.act == "*")
```
- `NewEnforcer(db *gorm.DB, modelPath string, tablePrefix string) (*casbin.Enforcer, error)`：用 gorm-adapter 绑定 `{{TABLE_PREFIX}}casbin_rule`，加载 `modelPath`，关闭适配器自动建表。
- 提供鉴权中间件骨架 `func Authz(e *casbin.Enforcer, subjectFn func(c *gin.Context) string) gin.HandlerFunc`：从上下文取 `obj=path`、`act=method`，`Enforce` 失败返回 `ERR_FORBIDDEN`（403）。`subjectFn` 由消费方注入（如从 JWT claims 取 sub），底座不假设主体来源。
- 本片只验「enforcer 能加载 model、能读写 DB policy、中间件能拦截」；**不**预置任何业务策略行。

### 4.4 跨语言加密向量（`server/spec/crypto-vectors/`）

> 向量中 IV 为**固定值**（保证确定性，可跨语言逐字节比对）；生产用随机 IV。所有 key 以 base64 表示，二进制以 hex/base64 表示。

`aes_cbc.json`：
```json
[
  {
    "name": "ascii_short",
    "aes_key_b64": "<32字节base64>",
    "iv_hex": "00112233445566778899aabbccddeeff",
    "plaintext_utf8": "hello-benxin",
    "ciphertext_b64": "<IV不含、仅密文的base64>"
  }
]
```
`hmac_sha256.json`：
```json
[
  { "name": "basic", "hmac_key_b64": "<base64>", "message_utf8": "abc", "signature_b64": "<base64>" }
]
```
`envelope.json`（端到端，含确定性 IV，验证完整信封与签名串）：
```json
[
  {
    "name": "post_json",
    "aes_key_b64": "<base64>",
    "hmac_key_b64": "<base64>",
    "iv_hex": "<16字节hex>",
    "method": "POST",
    "path": "/api/c/echo",
    "timestamp": "1750000000",
    "nonce": "abc123nonce",
    "plaintext_utf8": "{\"msg\":\"hi\"}",
    "expected_body_b64": "<base64(IV||cipher)>",
    "expected_signing_string": "POST\n/api/c/echo\n1750000000\nabc123nonce\n<body_b64>",
    "expected_signature_b64": "<base64(hmac)>"
  }
]
```
- 执行端用 Go 实现生成真实值填入（≥3 条/文件，含 1 条多字节中文、1 条空体边界）；`crypto/vectors_test.go` 反向加载断言加解密、签名、信封一致。
- `expected_signing_string` 中的 `<body_b64>` 写成实际值（不留占位），供 PHP 端逐字符 diff。

## 5. 安全要求（对照架构文档 §8 宪法级「安全第一」）
1. **Encrypt-then-MAC**：HMAC 覆盖 `IV||ciphertext` 经 BODY_B64 体现；先验签名后解密，杜绝 padding oracle。
2. **恒定时间比较**：签名/密钥比对用 `hmac.Equal`，禁用 `==`/`bytes.Compare` 早退。
3. **防重放**：时间窗 + 一次性 nonce；nonce TTL(600s) > 2×window(300s) 确保窗口内重放必被捕获；先验时间签名再落 nonce。
4. **密钥治理**：密钥/secret 全部配置注入，**严禁**代码内默认密钥或测试密钥泄漏到生产路径；启动 fail-fast。
5. **JWT**：HS256；校验 `exp/nbf/iss/tt`；黑名单覆盖刷新轮换与注销；refresh 默认轮换并拉黑旧 jti，防 refresh 重用。
6. **越权**：Casbin `Enforce` 失败一律 403；中间件不得在鉴权失败时泄漏策略细节。
7. **错误信息**：对外只回错误码 + i18n message，不回明文密钥/堆栈/解密细节；解密/签名失败统一为模糊提示，避免侧信道。
8. **参数化即安全**：底座代码 grep 不到 `kp_`/`okp`/`BenxinKP`/任何写死密钥。

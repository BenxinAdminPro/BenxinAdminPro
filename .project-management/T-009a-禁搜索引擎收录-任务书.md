# 任务书归档：T-009a 后台禁搜索引擎收录（noindex 三件套）

> 归档自 PM 下发任务书。完成报告见 `reports/T-009a-report.md`；退回修复单见 `T-009a-退回修复单-robots编码.md`。

**任务编号**：T-009a
**切片名称**：后台禁搜索引擎收录（noindex 三件套 · 后端中间件参数化 + 前端构建期固定兜底）
**目标后端**：Gin（Go）+ admin（前端静态）
**契约版本**：openapi 不升版（响应头非 API 端点契约）
**前置依赖**：无（独立小片，纯增量）

## 1. 目标
让管理后台默认禁止被搜索引擎收录（登录页/接口路径被爬是攻击面），且是否禁止可由部署配置控制（守底座中立，私有化可关）。

## 2. 范围
- ✅ 三件套：
  1. 后端 X-Robots-Tag 全局中间件（唯一碰 Go 的件，参数化权威控制点）：对所有响应注入 `X-Robots-Tag`，开关 + 内容走静态配置，默认开、默认 `noindex, nofollow`，关 → 不注入。
  2. admin `public/robots.txt`（`User-agent: *` + `Disallow: /`，Vite 拷站点根）。
  3. admin `index.html` head 加 `<meta name="robots" content="noindex,nofollow">`。
- ⛔ 不含：
  1. 前端参数化（A1 裁决·daxing 定）：robots.txt/meta 构建期写死，不做运行时/构建期 env 联动；权威可配置点是后端中间件。私有化放开 = 关后端开关 + 手删 robots.txt/meta（部署文档）。
  2. 行为验证码/WAF/IP 白名单等（noindex 只防"被收录"，根本正路是内网/VPN/不挂公网 DNS，属部署形态另记）。
  3. 无 DDL/错误码/权限码/openapi 端点。

## 5. 安全要求
- 默认安全：配置缺省 = 注入开 + `noindex, nofollow`，不可因配置缺失静默放开收录。
- 参数化不破坏默认安全：开关可关，但默认值必须是禁收录。
- 中间件对所有响应无差别注入，不碰鉴权/不依赖请求上下文/不查 DB。

## 6. 规范约束
- 代码头注释五项到秒（新增中间件文件）；改既有文件追加 @updated。
- 底座中立·参数化：中间件不硬编码 `noindex, nofollow` 字面到逻辑分支；开关 + 内容均从配置读，默认值集中一处定义。
- 配置项命名沿用既有 config 段惯例（执行端核实后回报）；中间件注册沿用既有全局中间件写法。

## 7. 验收标准
- 执行端：`go build && go vet && go test ./...`；中间件四态单测（开默认/关/自定义/缺省→默认安全）；admin `pnpm build` 产物根含 robots.txt + index.html head 含 robots meta。
- daxing：后端重启后 curl 任一端点响应头含 `X-Robots-Tag: noindex, nofollow`；浏览器 `/robots.txt` 返 `Disallow: /` + 页面 head 含 meta；（可选）关开关重启确认头消失。

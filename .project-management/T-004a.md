# 任务书

**任务编号**：T-004a（T-004 系统管理 第 1/2 子切片）
**切片名称**：response 完整包络接管 errcode 注册表 + 字典 + 参数 + 操作日志 + 登录日志
**目标后端**：Gin（纯 Go；本切片不碰 PHP）
**契约版本**：`server/spec/openapi/openapi.yaml`（v0.5.0 → 升 `v0.6.0`）
**前置依赖**：T-001（errcode 段注入、统一包络雏形）、T-002（登录日志数据源：登录成功/失败事件）、T-003（用户/角色，操作人主体；Authz/JWT；hashid）。

> **T-004 拆分**：**T-004a（本片）** = response 接管 + 字典 + 参数 + 日志；T-004b = 文件管理 + 存储驱动（独立任务书）。

---

## 1. 目标（一句话）
让 `response` 模块成为统一响应包络与**集中错误码注册表**的归属地（各模块注册自己的码、保留既有段语义，不破坏 T-001~T-003 已用码），并交付字典、参数、操作日志、登录日志四个通用系统管理能力。

---

## 2. 范围

### ✅ 包含
1. **`server/response/`** — 统一响应 + 错误码注册表（**本片最敏感、头号约束见 §4.1 / §5.1**）：
   - 统一包络渲染：`Success(data)` / `Fail(code)` / `FailMsg(code, msg)` / 分页包络；HTTP 状态映射。
   - **中心 `Registry`：各模块在 init/装配时注册自己的 (code, httpStatus, i18nKey)**；response 不硬编码任何模块的码。
   - 迁移 T-001~T-003 现有「最小错误码契约」到此 Registry：**既有 code 数值与段语义完全保留**，仅改为集中登记 + 统一渲染。
   - i18n 消息查找（key→message，语言可选；默认中性/中文）。
2. **字典**：`sys_dict_type`（字典类型）+ `sys_dict_data`（字典项）模型 + DDL + CRUD（类型/项分别 CRUD，按 type 查项）。
3. **参数**：`sys_config`（系统参数 key-value）模型 + DDL + CRUD（按 key 查）。**本片纯 DB，不做 Redis 缓存/热加载（留 T-005 配置中心）**。
4. **操作日志**：
   - `sys_oper_log` 模型 + DDL。
   - **中间件自动采集**：记录操作人(sub)/方法/路径/perm code/IP/UA/请求摘要/结果码/耗时；**可配置排除列表**（如 GET 查询、健康检查、登录接口本身）。
   - 异步写入（channel + worker 或直接 goroutine，避免阻塞请求；失败不影响主流程，仅告警日志）。
   - 列表查询（按操作人/时间/路径过滤）+ 清空/按时间清理。
5. **登录日志**（补 T-002 落库）：
   - `sys_login_log` 模型 + DDL。
   - 提供 `LoginLogger` 接口 + GORM 实现；**T-002 的 AuthService 通过接口注入记录**登录成功/失败（用户名/IP/UA/结果/原因），不在 auth 包直接依赖 DB（保持 auth 业务中立、DI）。
   - 列表查询 + 清理。
6. spec：openapi 升 v0.6.0（字典/参数/日志路径 + schema）；错误码段总表纳入 spec（供 PHP parity）。
7. 单测（Registry 注册/查找/冲突检测、包络渲染、字典参数 CRUD、操作日志中间件采集与排除、登录日志接口注入，docker-free）+ 集成测试 `//go:build integration`（真 MySQL 验日志落库与查询）。

### ⛔ 不包含
- 文件管理 + 存储驱动 → **T-004b**。
- 参数/字典的 Redis 缓存与热加载 → **T-005 配置中心**（本片纯 DB）。
- 配置中心驱动化/加密存储 → T-005。
- 前端 → admin 切片。

## 4. 接口契约

### 4.1 错误码注册表迁移（头号约束）
```go
// server/response
type ErrSpec struct { Code int; HTTP int; I18nKey string }
type Registry interface {
    Register(spec ErrSpec) error // 重复 code → 冲突 error（启动 fail-fast）
    Lookup(code int) (ErrSpec, bool)
    Render(c *gin.Context, code int)            // 按 code 取 spec，写包络 + HTTP 状态
    RenderMsg(c *gin.Context, code int, msg string)
}
```
- **既有码零变更**：T-001/T-002/T-003 已用的 code 数值、段基址注入机制、HTTP 映射、i18n key **全部保留**；迁移只是把分散定义改为各模块调用 `Register` 登记到中心。
- **段基址仍注入**：各模块 offset + 注入的段基址算出的最终 code 注册进来；response **不硬编码**任何模块的具体码。
- **冲突检测**：重复 code 注册 → 启动 fail-fast（防迁移漏改或段重叠）。
- **业务码可注册**：消费方业务模块也能 Register 自己的段，response 不预知（业务中立）。

### 4.2 操作日志中间件
```go
type OperLogConfig struct {
    Enabled       bool
    ExcludePaths  []string   // 前缀/精确，配置注入
    ExcludeMethods []string  // 如 ["GET"]（可配）
    BodyMaxBytes  int        // 请求摘要截断
}
func OperLog(cfg OperLogConfig, sink OperLogSink, subjectFn func(*gin.Context) string) gin.HandlerFunc
type OperLogSink interface { Write(ctx, OperLogEntry) error } // GORM 实现 + 异步包装
```
- 异步写入，主流程不阻塞、写失败仅告警不影响响应。
- 排除列表配置注入（默认排除登录/健康检查/纯查询可配）。

### 4.3 登录日志（补 T-002）
```go
// server/response 或 server/system 定义接口；auth 通过依赖注入使用，不直接 import DB
type LoginLogger interface { Log(ctx, LoginEvent) error }
```
- **改 T-002 AuthService（既有文件，追加 @updated）**：在登录成功/失败分支调用注入的 `LoginLogger`（可空——为空则跳过，保持向后兼容与 DI）。
- auth 包**不新增对 GORM 的直接依赖**；LoginLogger 的 GORM 实现放 system/response 侧，由装配注入。

## 5. 安全要求
1. **迁移不破坏既有码（头号）**：T-001~T-003 全部错误码经回归测试确认数值/HTTP/语义不变；冲突检测启动 fail-fast；spec 错误码总表与代码一致。
2. **日志脱敏**：操作日志 req_summary **不得记录**密码、验证码答案、token、password_hash 等敏感字段；登录日志只记用户名/IP/UA/结果/原因码，不记密码。需有脱敏白/黑名单或字段过滤，且有测试。
3. **日志不阻塞、不放大故障**：异步写入；日志写失败只告警，绝不影响主请求结果。
4. **日志接口需鉴权**：日志列表/清理挂 RequirePerm；清理为高危操作，权限码独立。
5. **DI/业务中立**：auth 不因登录日志而依赖 DB（走 LoginLogger 接口注入）；response Registry 不硬编码业务码；service 不 import config；前缀随实例；grep 无硬编码专属值。
6. **参数值安全**：sys_config 可能存敏感参数——本片纯 DB 明文存储即可，但**注释标注**敏感参数加密存储留 T-005 配置中心（不在本片造半套加密）。

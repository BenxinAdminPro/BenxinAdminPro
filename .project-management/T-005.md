# 任务书

**任务编号**：T-005
**切片名称**：配置中心 — 动态参数缓存 + 热加载（Redis Pub/Sub）+ 敏感值 GCM 加密存储 + SQL 迁移执行器
**目标后端**：Gin（纯 Go；本切片不碰 PHP）
**契约版本**：`server/spec/openapi/openapi.yaml`（v0.7.0 → 升 `v0.8.0`，若参数接口有字段增量）
**前置依赖**：T-001（crypto 提供 AES 能力可复用/扩展为 GCM、Redis 接口模式）、T-004a（sys_config / 字典 CRUD，本片为其加缓存/热加载/加密）、T-004c（response 唯一渲染，已就位）。

> **性质**：本片大量是"接管 T-004a 留的尾巴"——字典/参数当时声明缓存+热加载留 T-005、sys_config 敏感值加密留 T-005、spec SQL 的 {{TABLE_PREFIX}} 迁移执行器一直挂着。本片把这三笔债一起还掉。**边界：聚焦动态参数；静态启动配置仍归 viper，不纳入本片。**

---

## 1. 目标（一句话）
让 sys_config / 字典从"纯 DB"升级为"带 Redis 缓存 + Pub/Sub 热加载 + 敏感值 GCM 加密"的配置中心；并提供正式的 SQL 迁移执行器（替换 {{TABLE_PREFIX}} 占位、按序执行、记录版本），使 demo 能一键初始化。

---

## 2. 范围

### ✅ 包含
1. **配置缓存层**（`server/config/center/` 或 `server/system/configcenter.go`，命名执行端定）：
   - 参数/字典读经缓存（Redis，key 前缀注入）；未命中回源 DB 并回填。
   - 写（创建/更新/删除参数或字典）→ 失效相关缓存 + 发 Pub/Sub 通知。
   - 缓存接口化（`ConfigCache` 接口 + Redis 实现 + 内存假实现），延续存储分层。
2. **热加载（Redis Pub/Sub）**：
   - 写操作发布变更消息（channel 名前缀注入，如 `{prefix}:config:changed`，payload 含变更 key/类型）。
   - 各实例订阅，收到即失效/刷新本地或 Redis 缓存；**单实例时退化为本地直接刷新**（无 Redis 也能跑，假实现兜底）。
   - 订阅协程优雅启停（随应用生命周期），断线重连。
3. **敏感参数 GCM 加密存储**（还 T-004a 债）：
   - `sys_config` 增列 `is_encrypted TINYINT`（既有表增量迁移，改 T-004a 模型追加 @updated）。
   - 加密：AES-256-**GCM**（认证加密），加密主密钥**配置注入**；建议复用/扩展 T-001 crypto 包能力（新增 GCM 函数，与 T-001 CBC 并存，不破坏 C 端信封）。
   - 写入 is_encrypted=1 的参数时加密存库；读出时自动解密；**响应/日志绝不回明文密钥**（敏感参数值脱敏或仅授权接口可见，见 §5）。
   - 存储格式：随密文存 nonce（GCM 需要），格式自描述便于解密；跨语言可解（PHP parity 友好，注释/spec 说明格式）。
4. **SQL 迁移执行器**（还历史债）：
   - 读取 `server/spec/migrations/*.sql`，按文件名/版本排序，`{{TABLE_PREFIX}}` 替换为注入前缀，按序执行。
   - 记录已执行版本（`sys_migration` 或等价表），幂等：已执行跳过；失败中止并报告。
   - 提供 CLI 入口或 demo 可调用的函数；集成测试用它建表（替代此前手动 ReplaceAll）。
5. **参数/字典接口增量**：创建/更新参数支持 is_encrypted 标记；其余 CRUD 沿用 T-004a（本片只加缓存/加密维度，不改既有语义）。
6. spec：openapi 升 v0.8.0（如 sys_config 增 is_encrypted 字段）；GCM 存储格式纳入 spec（PHP parity）；迁移执行器约定纳入 spec。
7. 单测（缓存命中/失效/回填、GCM 加解密往返与篡改检测、热加载发布订阅用假实现、迁移执行器排序/替换/幂等，docker-free）+ 集成测试 `//go:build integration`（真 Redis 验缓存+Pub/Sub 跨实例刷新；真 MySQL 验迁移执行器建表 + 加密参数落库解密）。

### ⛔ 不包含
- 静态启动配置（DB/Redis/密钥/JWT TTL 等 viper 管的）→ 仍归 viper，不纳入。
- 配置版本回滚/灰度/审批流 → 后续，不在本片。
- 前端配置管理页 → admin 切片。
- 多租户级配置隔离 → 后续扩展。

## 4. 接口契约

### 4.1 ConfigCenter / 缓存接口
```go
type ConfigCache interface {
    Get(ctx, key string) (string, bool, error)
    Set(ctx, key, val string, ttl time.Duration) error
    Del(ctx, keys ...string) error
}
type ConfigCenter interface {
    GetConfig(ctx, key string) (string, error)      // 缓存→回源 DB→回填；自动解密 is_encrypted
    GetDict(ctx, dictType string) ([]DictItem, error)
    // 写经各自 service，写后由 center 失效缓存 + 发布变更
    OnChange(payload ChangeEvent)                    // 订阅回调：失效/刷新
}
```
- 依赖（构造注入）：`*gorm.DB`、`ConfigCache`、发布订阅器、`Crypter`（GCM）、前缀/主密钥/TTL；**不 import 全局 config 包**（延续 DI）。

### 4.2 GCM 加密（crypto 包增量，与 T-001 CBC 并存）
```go
// server/crypto —— 新增 GCM（存储场景，认证加密），不动既有 CBC（C 端信封）
func EncryptGCM(key, plaintext []byte) (ciphertextWithNonce []byte, err error) // nonce 前缀/自描述
func DecryptGCM(key, data []byte) (plaintext []byte, err error)                // 篡改→认证失败 error
```
- 主密钥从配置注入（base64，解码须 32 字节，启动 fail-fast）。
- 存储格式（spec 注明）：`base64( nonce(12B) || ciphertext || tag )` 或等价自描述格式，PHP 可解。

### 4.3 热加载 Pub/Sub
- channel：`{redis_prefix}:config:changed`（前缀注入）。
- 发布：参数/字典写成功后发布 `{type, key}`。
- 订阅：应用启动起订阅协程，收到失效对应缓存；单实例无 Redis 时走本地失效（假实现）。
- 优雅关闭：context 取消时退出订阅。

### 4.4 迁移执行器
```go
type Migrator struct { db *gorm.DB; prefix string; dir string }
func (m *Migrator) Up(ctx) error  // 排序→替换{{TABLE_PREFIX}}→未执行的按序 Exec→记 sys_migration；幂等；失败中止
```
- 排序规则明确（文件名前缀序号，如 T001_/T003a_…需可排序；执行端定排序键并说明）。
- 幂等：已记录版本跳过。失败：中止、报告未完成项、不静默。

### 4.5 错误码增量（注册进 response.Registry）
ERR_CONFIG_DECRYPT_FAILED(500) / ERR_MIGRATION_FAILED(500) / ERR_CONFIG_KEY_NOT_FOUND（复用 T-004a 或新增，避免重复）。

### 4.6 OpenAPI 升 v0.8.0（sys_config is_encrypted 字段等）；GCM 格式 + 迁移约定纳入 spec；redocly 0 error。

## 5. 安全要求
1. **敏感值加密（头号）**：is_encrypted 参数 GCM 加密存库；主密钥配置注入、禁硬编码、启动 fail-fast；密文随存 nonce；解密失败（含篡改）报错不静默返回脏数据。
2. **明文不泄漏**：加密参数的明文值**不得**出现在列表/日志/操作日志中；读接口返回加密参数时，默认脱敏（如 `******`）或仅特定授权接口可取明文（执行端定策略并说明，默认脱敏）。
3. **GCM 正确性**：每次加密用唯一 nonce（随机/计数器，禁重复）；认证标签校验；篡改检测有测试。
4. **缓存一致性**：写后失效 + Pub/Sub 通知，避免脏读；缓存失效失败不导致返回旧密文当明文等错误；缓存 miss 安全回源。
5. **迁移执行器安全**：只执行 spec/migrations 下受信 SQL；前缀替换不引入注入（前缀来自配置非用户输入）；幂等防重复执行；失败中止保留现场。
6. **不破坏 T-001 C 端加密**：新增 GCM 与既有 CBC 信封**并存互不影响**；C 端信封仍是 CBC（跨语言向量不变），GCM 仅用于存储。回归 T-001 crypto 测试全绿。
7. DI/参数化：center/crypter/migrator 不 import config 包；前缀/密钥/TTL 注入；前缀随实例；grep 无硬编码专属值。
